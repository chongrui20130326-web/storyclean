# 小说清洗软件

独立移植《小说分析器》的前四步。保留原版操作、正文处理和编号格式，使用独立的书库、设置和日志。

## 启动

需要 Node.js 22 或更高版本。首次使用时在本目录运行 `npm ci` 安装依赖，然后双击 `start.cmd` 或运行 `npm start`，打开 [本地工作台](http://127.0.0.1:4186/)。端口占用时可运行 `.\start.cmd 4187`。原小说分析器可独立运行。

右上角 **配置 LocalAI 模型** 会自动读取模型列表。可为小说清洗、正文复核、场景切分和生成角色真名表分别手填模型 ID 或从列表选择。保存后可在顶部核对各步骤使用的模型。正文复核模型留空时沿用小说清洗模型。默认网关是 `http://127.0.0.1:8090/v1`。新版首次读取前一版工作台的已保存配置。在本机网关上，场景和角色选择相同模型、清洗尚未单独选择时，清洗沿用该模型。其余未配置阶段可自动选择网关中可用的 `qwen3.5:4b`。

### 角色混合检索

在新目录使用混合检索时先运行 `npm ci`，并使用支持 `node:sqlite` 的 Node.js 22.13 或更新版本。设置中的「角色检索的向量模型」可填写 LocalAI 已提供的模型 ID，例如 `qwen3-embedding-0.6b`。先点「测试向量模型」，成功后保存。该测试使用已保存的网关。角色模型仍在「生成角色真名表」一栏单独选择。

混合检索使用 LangChain.js 和本地 SQLite，从当前书已处理的场景检索证据。索引按批保存，后续会复用。向量模型留空或调用失败时，会使用原句检索。已经核对完当前场景的书籍可以点「复核待确认身份」，保留已保存的逐场结果。跨场身份与动作证据可在第 4 步和第 5 步查看，随角色记录导出。

## 原版四步

1. **小说清洗**　选 TXT 或 MD，点「开始清洗」。沿用原版模型书名与目录识别、结构目录策略、章节复核和正文规则清洗。可勾选「正文模型复核」。左侧分别预览书名、目录、正文，右侧查看检查报告。点「保存并编号」后自动更新书库。
2. **内容编号**　可打开已保存的书籍，也可独立选择小说文件，用「开始编号」「更新书籍」处理。保留原版自底向上的章、段、句编号、覆盖率、警告和正文定位。标题所在的句号按原版规则保留，章前文字另存于工程。
3. **场景切分**　选书后点「开始切分」。每次把约 5000 字的完整句交给模型判断情节转场。有有效切点时，下一批从上批未成场的第一句重新组批。成场至少 20 个编号句，结尾不足 20 句会并入前场。连续叙述可以跨章和跨批，单场可以超过 5000 字。整段没有切点时，程序保留未成场内容并继续往后查找。全文不足 20 句时保留一场并说明原因。点击左侧场景可查看正文，停止后能从已保存的滚动起点继续。
4. **生成角色**　点「按场景生成真名表」核对已经切分出来的场景。每场保存后立即显示「确认出场」「仅被提及」和「待确认」，点击证据可定位原句。本场称呼随证据保存在对应场景。处理完已切分的场景后，对仍未确认身份的人物从同一本书的已处理原文检索身份句。有明确身份依据时回填相关场景，可分别查看本场出场证据和跨场身份依据。证据校验失败时会缩小当前片段，中断后点「继续逐场生成」。全书分析完成后可点「生成场景内人称」，并在场景原文中查看高亮。同句关系保存在附表中。
5. **文件查看**　左侧列出已生成的文件和用途。点开后默认显示「数据解读」，按文件内容展示中文统计、分页记录和可展开的原文证据。还可切换到「数据结构」或「JSON 内容」，以及下载原文件。大文件按中文字段逐层展开，超过树形查看上限时仍可逐页阅读和下载。

生成正式人称表后，在第 4 步点「开始人称映射」。本场先结合原句、对白和角色证据判断。对本场无法确认、跨场又有明确身份和事件线索的记录，复用书籍检索进行复核。已映射的人称会标成绿色，点击记录可查看证据并定位原句。界面显示当前阶段的预计剩余时间。每场保存一次进度，停止后可继续。映射模型可单独选择，留空沿用真名模型。向量不可用时仍可按原句检索。

「一键处理并导出」顺序生成到正式人称表。已保存的阶段会复用。运行期间保持页面打开，可自动下载工程。后台场景任务保留已提交批次，停止后再次启动即可续跑。

## 书籍工程与数据

「导出工程」生成 `novel-cleaning-project` v2。包括原稿字节及 SHA-256、清洗目录正文和报告、原版编号和正文位置、书籍章段句结构、原始代词索引及已生成的场景、逐场角色证据、真名、人称与映射。再次导入会核对覆盖、场景范围、证据原句和人称位置，并新建书籍。可在只完成编号时导出初始工程。导入前一版 v1 工程可载入其中的原稿，按原版重新清洗和编号。

新版书库位于 `data/analyzer`，其他版本的书稿和项目仍可在各自的目录打开。前一版独立工作台可用 `node server.mjs 4187` 启动。LocalAI 密钥保存在本地设置，工程仅包含书籍数据。

## 验证

- `npm test` 覆盖原版提取后的清洗、编号、场景断点、角色、人称和工程回环，以及前一版项目格式的回归。
- `node scripts/analyzer-parity.mjs` 用同一原稿、同一组模拟模型答复对照旁边目录的原分析器。对比清洗报告、编号、书籍结构、真名表及人称记录，并核对当前最少句数规则对小样本场景范围的影响。
- `node scripts/browser-smoke.mjs --analyzer` 检查四个原版入口、模型设置、人称高亮、一键下载和工程回导。

原版场景以书籍章节正文为范围。章前文字仍保留在原始编号和导出工程里。独立编号若未识别到章节，可先走「小说清洗」补齐目录，再启动场景切分。当前验收以小样本完成。
